# 第二阶段实施设计与验收约定

本阶段依据《大作业一：需求变更.docx》和课堂补充，在原系统上增加题库与版本功能。第一阶段快照stage1-submission-20261023指向0cdfefd。原账号、问卷、进度、答卷、业务规则和38项测试记录保留。

## 数据与版本

新增question_banks和library_questions；题目定义使用第一阶段同一校验器。library_questions含owner_id、bank_id、shared_with、working_copy、versions[]、revision。versions[]每项含独立版本ID、顺序号、parent_version、restored_from、题目内容及created_at。已提交版本永不覆盖；同一文档内条件更新，确保历史和修订号一起变化。版本数暂限100，避免无界增长，后续可拆独立集合。

“是否创建新版本”：false只保存私有工作稿，不改变任何已存在版本；true从工作稿/本次输入提交新版本。恢复旧版本时创建新版本并记录restored_from，保留旧历史，不能误用revision/schema_version表示业务版本。该语义为本项目对未明确细节的设计选择，不称作教师指定。

## 导入与保护

选择某题的确切版本后，复制完整定义到草稿问卷，记录source.library_id/version/definition_hash。新题使用本问卷局部ID，源题后续修改不自动同步到旧问卷。源题不携带其他问卷跳转目标：题库定义不含跳转；从旧问卷保存到题库时显式移除上下文跳转并在结果提示，导入后由创建者配置。发布问卷仍冻结，改答/进度/单卷统计逻辑不变。

本卷修改已导入题时保留来源，统计按实际定义摘要分组，不能将改过题型/选项/含义的回答混算。标题、约束等变化也保守分组，不暗示语义兼容。

## 权限与范围

题库由本人管理；题目可按用户名分享只读使用权，分享不授予编辑权或问卷答卷读取权。撤销分享阻止后续读取/导入，已有问卷副本保留。来源题主可见使用数量；他人的问卷不返回标题/链接/答案，仅匿名计数。当前用户仅能聚合自己有管理权限的问卷，分享题目不意味着可读取他人答案。

## 八项验收

| 要求 | 主要验收 |
|---|---|
| 常用题保存复用 | 从定义或本人问卷保存，导入多个草稿 |
| 分享 | 允许指定账号读取使用，未授权/撤销后拒绝，不能代改 |
| 旧问卷保护 | 原始快照与答卷不随源题改变 |
| 历史恢复 | parent与restored_from明确，历史不覆盖 |
| 多版本 | 指定不同版本导入不同问卷 |
| 使用追踪 | 局部题ID、来源版本、本人列表和他人计数 |
| 题库管理 | 建立分组、管理题目、选择题目和版本 |
| 跨卷统计 | 保留单卷统计；按版本与实际定义摘要分组，多选分母为有效回答次数 |

逻辑测试检查定义与版本，真实MongoDB API测试检查状态、权限、快照、恢复、并发、聚合。测试在随机测试库执行；阶段二结果单独保存，不覆盖第一阶段latest.json。当前完整52项测试通过，浏览器导入、工作稿、版本、恢复和统计流程已验证，步骤与结果见[API与测试说明](API与测试说明.md)。
