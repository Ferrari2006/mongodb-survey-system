## 设计取舍

题目、选项、约束和跳转随问卷一起读取，因此仍嵌入问卷。正式答卷持续增加，独立保存。题库的工作稿、历史与当前指针在同一文档中，借助revision条件更新一起写入，避免两个请求互相覆盖。

导入时复制指定版本并记录来源，题库更新不覆盖旧问卷。允许调整本卷副本，但实际定义改变后另分统计组。恢复追加新版本，父版本与恢复来源分别记录。历史内嵌简化读取和原子更新，也意味着需要限制增长：当前每题最多100个已提交版本。

默认统计本人问卷；题主可选择全部已授权问卷汇总。位置公开与统计授权分别控制，文本原文不对外开放。数字使用自动分桶，文本在后端分页。更详细的字段、索引与设计依据见[实施设计](实施设计-2026-10-23.md)和[API与统计口径](API与测试说明.md#版本语义与统计口径)。

### 复核一条完整流程

双账号结果可复核：作者共享题目，接收者导入首版、发布并回答2；作者更新源题后，旧问卷仍用原内容；作者自己的问卷回答8。双方统计分别保留2与8。撤销共享后，接收者读取源题失败，但已导入副本仍可使用。恢复追加版本，不覆盖原历史。

## 实现边界与后续验证

| 边界 | 当前状态 |
|---|---|
| 历史版本容量 | 每题最多100版；长历史独立集合尚未实现 |
| 跨用户汇总 | 已实现；题主汇总获授权的外部引用，原始答卷保持隔离 |
| 本卷改题 | 保留来源、按实际定义另分组；不是自动同步源题 |
| 并发修改 | 相同revision更新的冲突处理已有测试 |
| 共享撤销与导入同时发生 | 普通先后请求已验证；跨文档竞争尚未专项验证。导入先查权限再保存问卷，不能据此宣称具备事务隔离 |
| 查询效率 | 已配置索引，尚未保存本项目专门的explain执行计划或生产规模性能证据 |
| 运行范围 | 本机MongoDB与Chromium；尚未公网部署、压测或验证所有浏览器 |

后续优先补共享撤销竞争场景、来源查询执行计划，以及本卷改题状态提示。它们是后续验证或改进项，不计入当前通过的58项测试。
