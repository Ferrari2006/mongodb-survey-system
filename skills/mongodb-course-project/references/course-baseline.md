## 文档明确要求

- 开发简化在线问卷系统，类似问卷星或 Google Forms，可用简单网页。后端 MongoDB，语言和框架不限；所有业务数据存 MongoDB，不用关系数据库，不用现成问卷系统框架。
- 第一阶段完成系统设计、数据库、前后端、必要测试、文档和完整报告。第二阶段基于第一阶段修改，不推倒重做；保留核心结构、主要功能和旧数据，说明兼容性及回归验证。
- 用户注册和登录，包含用户名、密码信息和注册时间；创建者只能管理自己的问卷。填写者也须登录。
- 问卷有标题、说明、匿名设置、创建者列表、发布、截止时间、关闭和访问链接。
- 单选支持选项及必答；多选支持最少、最多、恰好选择数量；填空支持文本长度和数字范围、整数限制。
- 跳转根据单选、多选、数字回答配置，不能把某份问卷规则写死在程序中。
- 按顺序和规则答题，错误提示，提交保存；支持多人填写、匿名以及设置允许时重复填写。
- 单选统计各选项数量及回答总数；多选统计各选项次数；填空列出内容，数字求平均；支持整卷和单题统计，由保存数据生成。
- 必须真实记录 AI 工具、提示词、得到的代码、是否修改及修改内容；报告总结 AI 帮助、错误、学生修改和设计。
- 测试至少覆盖创建问卷、添加题目、跳转、校验、提交、统计。可自动、手工或 API 测试，必须说明步骤。
- 两阶段均交代码（含后端、Schema、配置说明）、文档（系统、数据库、API、关键逻辑）、测试用例（步骤、输入、输出、结果）、报告（目标、系统设计、MongoDB、跳转、校验、AI、测试、问题及解决）。
- 评分：MongoDB 35，后端 25，测试 10，文档 15，AI 15。总成绩为阶段一 30% 加阶段二 70%。

## 方案建议

- 可选 users、surveys、responses；题目嵌入问卷，答卷独立保存。需根据规模和读取方式讨论，不固定唯一方案。
- 密码保存哈希；题目及选项采用稳定 ID；按发布和修改策略考虑版本或结构冻结。
- 对答卷增长、规则冲突、非法目标和循环、过期提交、越权和并发重复提交作出明确设计。
- 索引由查询和约束决定，聚合可使用 match/unwind/group/avg 等，但无需机械使用所有实验操作。
- 第一阶段用版本控制保存基线；第二阶段说明变更原因、修改位置、数据迁移和回归结果。
