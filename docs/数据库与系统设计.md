# 数据库与系统设计

系统使用Flask、PyMongo及原生网页，按认证、问卷管理、题目校验、路径解释、统计划分模块。技术方案由AI辅助提出和实现，学生的需求引导与实际采纳过程见ai_logs。

## 集合和Schema

| 集合 | 主要字段 | 原因 |
|---|---|---|
| users | _id、username、password_hash、created_at | 独立账号，密码带盐哈希 |
| sessions | _id（令牌SHA256）、user_id、expires_at | 会话也存MongoDB，可撤销、过期 |
| surveys | _id、owner_id、title、description、status、allow_anonymous、allow_repeat、deadline、questions、revision、schema_version、created_at、updated_at、published_at | 题目随问卷整体读取，嵌入保存 |
| fill_progress | _id、survey_id、user_id、survey_revision、revision、answers、anonymous、request_id、updated_at | 每账号每问卷一份已确认进度，独立于正式答卷 |
| responses | _id、survey_id、user_id、anonymous、submission_key、request_id、survey_revision、answers、path、created_at | 一次提交一个文档，支持持续增长和统计 |

ID为字符串UUID，日期为BSON Date，版本为整数。questions项含id/title/type/required/validation/jumps，选择题另有options。answers是question_id/value数组，path记录实际经过题目。具体validator见backend/database.py和database/schema.json。

稳定ID使答案不依赖题号或文案。题型不同的规则自然表达为嵌套文档；题目整体嵌入减少读问卷时的关联查询；持续增长的答卷独立保存。关系数据库同样可以实现，本设计依据课程指定技术和访问模式选择MongoDB。

## 约束和索引

集合validator检查必要字段、顶层类型、合法状态；嵌套题目和业务规则由validation.py与logic.py检查。直接写库仍需遵守业务约束，数据库validator不能替代全部业务校验。

| 索引 | 用途 |
|---|---|
| fill_progress.survey_id + user_id唯一 | 每账号每问卷仅一份活动进度，revision防止多窗口覆盖 |
| users.username唯一 | 登录查询、并发注册防重名 |
| sessions.expires_at TTL | 自动清理；认证显式检查过期时间，避免TTL延迟 |
| surveys.owner_id + updated_at | 本人问卷列表和最近修改排序 |
| responses.survey_id + user_id + submission_key唯一 | 禁重复时固定once；允许重复时用request_id |
| responses.survey_id + user_id + request_id唯一 | 网络重试幂等 |
| responses.survey_id + created_at | 某问卷答卷分页 |

每集合另有_id索引。不添加没有查询或约束用途的索引。

## 发布和迁移

draft→published→closed。发布前检查非空、目标和截止时间。发布后固定结构和设置，避免旧答卷含义改变；第一阶段需要修改时创建新问卷。

草稿更新按_id、owner_id、revision和draft状态执行原子替换，成功版本递增；并发同版本只能一个成功。schema_version标识数据结构，revision标识编辑版本，不混用。

旧草稿validator仅允许draft，scripts/migrate_drafts.py显式扩展为三个状态并补充缺失设置。不删除旧文档，幂等执行；未知validator停止并要求检查。普通初始化不自动覆盖已有validator。自动化验证迁移保留数据。

## 跳转和校验

规则存questions.jumps，首条匹配生效；单选eq，多选any/all，数字eq/lt/lte/gt/gte。未匹配下一题，末题结束。仅向后或END，阻止循环。草稿可先引用未来题，发布时目标完整。

单题校验检查必答、合法选项、多选无重复/数量、文本长度、数字有限性/整数/范围；同时拒绝定义矛盾。文本去首尾空白后按Python字符数计算。数字拒绝布尔值、NaN、无穷、绝对值超过10^15。

evaluate重新解释路径，提交重算并拒绝路径外答案，被跳过必答题不参与校验。前端返回修改会清理后续答案。空选答不进入有效answers数组，在path保留经过记录。

## 匿名、重复和并发

所有填写者登录，匿名对创建者隐藏账号，内部保留user_id用于认证和限制重复；不声称不可追溯。创建者API剔除匿名身份及去重字段。

唯一索引防止同账号重复提交，不能只“先查再插”。request_id保证同一次网络重试不多计。关闭/截止并发采用survey原子准入更新：关闭前准入允许完成，关闭后新请求拒绝。admission_count是准入尝试数，失败或重复可能增加它，绝不作为有效答卷数。

本机单节点MongoDB不使用跨集合事务。不承诺跨集合事务原子性；准入后进程崩溃不会生成有效答卷，统计以实际responses为准，重试用同request_id保证幂等。

## 统计与运行边界

聚合match筛问卷，unwind展开answers，按question_id筛题；group/sum统计选项，多选再展开value；数字avg，填空投影value。补齐零次选项，空数字average=null。整卷和单题共用函数。

允许重复时按有效答卷份数，非独立人数。每次点击下一题校验成功后，进度写入fill_progress，同账号刷新或重新登录可恢复。进度仅保存有效路径前缀，返回时删除已确认后缀；匿名偏好也保存。当前题未确认输入不自动保存。乐观revision拒绝旧标签页覆盖；提交后清理匹配request_id的进度，统计仅查询responses。跨集合并发遗留的已提交进度在读取时清理；进度保存不承诺跨集合事务。新集合在启动时增量创建，不迁移或删除旧答卷。填空内容目前全部返回，适用于课程规模，后续可分页。

本地默认监听127.0.0.1，开发服务器；请求体256KiB、每卷100题、每选择题50选项。未进行生产部署、压力测试、HTTPS和限流。前端sessionStorage保存令牌，不在仓库存密钥。
