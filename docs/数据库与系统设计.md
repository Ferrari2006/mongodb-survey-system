# 账号与问卷草稿的设计说明

当前实现以 Python Flask 提供 HTTP API，以 PyMongo 访问 MongoDB，浏览器页面使用原生 HTML、CSS 和 JavaScript。选择这一组合是为了衔接前期 MongoDB 实验，并使业务校验、HTTP 接口和数据库职责清楚。技术选择由 AI 提出并实施，用户授权开始开发，尚未逐项确认后续业务歧义。

## 集合设计

| 集合 | 字段与类型 | 原因 |
|---|---|---|
| users | _id:string、username:string、password_hash:string、created_at:date | 账号独立存在；密码使用 Werkzeug 的带盐哈希，不在接口中返回 |
| sessions | _id:string（令牌SHA256）、user_id:string、expires_at:date | 登录状态保存在 MongoDB，退出后立即撤销；数据库不保存原始令牌 |
| surveys | _id:string、owner_id:string、title:string、description:string、status:string、questions:array、revision:int、schema_version:int、created_at/updated_at:date | 问卷与题目通常整体读取，题目嵌入文档；使用稳定ID，不依赖文字或数组位置标识题目 |

答卷拟独立存储，避免在一份问卷文档中无限增加答卷数组。responses 集合尚未创建，身份字段与版本关系将在匿名及发布策略确定后设计。sessions 是认证支撑集合，不是把原本三个候选业务集合全部原样实现。

surveys 的 questions 数组中每项包含 id、title、type、required、validation；选择题还包含 options，每个选项有 id、label。原题目的三类中，文本填空和数字填空在程序中分别标为 text 与 number，以便使用对应校验。

```json
{
  "id": "age",
  "title": "年龄",
  "type": "number",
  "required": true,
  "validation": {"min": 0, "max": 120, "integer": true}
}
```

## 嵌入与约束

将题目嵌入问卷，可用一次读取获得草稿和全部题目，更新时也能以一个文档作为并发控制单位。代价是局部题目更新仍需写回整个问卷，且不适合无限增长的题库。本里程碑限制每份问卷100题、每题50个选项，请求体256 KiB；这些是实现约定，不是课程指定数值。

MongoDB 的灵活结构用于容纳不同题型的配置，并非取消约束。backend/database.py 的 SCHEMAS 定义集合级必备字段、类型与当前状态。嵌套题目和业务规则由 backend/validation.py 严格检查。数据库级 Schema 目前只限制 questions 为数组，不能代替业务层完整校验；直接写库需自行遵守结构。

初始化仅为新集合设置 validator，不覆盖已有集合。第二阶段如修改 validator，需编写明确迁移步骤并验证旧数据。schema_version 表示结构版本，revision 表示当前文档编辑版本，两者不混用。

关系数据库也能实现问卷系统。本项目根据课程指定的 MongoDB 环境及问卷整体访问方式选择嵌套文档，不将题目、选项机械地拆成多张关系表。

## 索引

| 集合 | 索引 | 解决的问题 |
|---|---|---|
| users | username 唯一索引 | 防止并发注册重名，登录时按用户名查找 |
| sessions | expires_at TTL，expireAfterSeconds=0 | 自动清理过期会话；每次认证仍显式比较 expires_at，避免TTL清理延迟产生有效期漏洞 |
| surveys | owner_id升序、updated_at降序 | 按当前用户筛选并按最近修改排序 |

所有集合另有默认 _id 唯一索引。未添加没有查询依据的索引。

## 所有权和并发编辑

客户端通过 Authorization: Bearer 传递随机令牌；服务器查找令牌哈希对应的有效 session，从中获得 user_id。owner_id 由服务器设置，客户端不能指定。读写问卷时同时按问卷ID和owner_id筛选，对无权或不存在的问卷统一返回404。

保存请求带上读取时的 revision。后端使用 _id、owner_id、revision 和 draft 状态组成更新条件，一次原子替换并将 revision 加一。两个请求携带同一版本时只有一个成功，另一个返回409，避免先读再写导致的静默覆盖。此机制是编辑冲突控制，尚未扩展至答卷提交。

## 校验边界

- 单选只能提交一个合法选项ID；多选必须是ID数组，无重复且数量满足上下限；上下限相同表示恰好选择该数量。
- 文本去除首尾空白后按 Python 字符数判断长度；选答题可留空，非空时仍检查限制。
- 数字拒绝布尔值、字符串、NaN和无穷大；允许绝对值不超过10^15的有限数字；整数限制检查数值是否为整数。
- 题目定义本身也被检查，例如最小值大于最大值、重复选项ID、不适用字段、必答题上限为0均拒绝。
- 单题预览只验证当前题，尚未决定跳转后哪些题构成有效答题路径。

## 当前运行限制

应用默认只监听127.0.0.1，使用 Flask 开发服务器供课程本地演示。尚未配置公网部署、HTTPS、登录限流和生产运维。本地页面通过 sessionStorage 保存会话令牌，刷新页面可恢复会话；不得将生产安全能力表述为已完成。
