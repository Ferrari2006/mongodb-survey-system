# 第一阶段参考对照与优化

本文件供学生理解差异与报告复核。来源为用户2026-10-22提供的邵子翀、杨子炫第一阶段PDF、第一阶段课程原文及本项目实际代码。参考项目未提供本次可运行源码，因此下表左列是作者报告描述，不是独立代码审计或运行结论。

## 1. 与邵子翀报告的技术差异

| 比较项 | 参考报告描述 | 本项目实际实现与取舍 |
|---|---|---|
| 技术栈 | Vue/TypeScript、Node.js/Fastify、MongoDB | Python/Flask、PyMongo、原生网页；复用已有实验环境，后端模块独立测试 |
| 数据模型 | users、surveys、survey_versions、responses；问卷编辑内容与发布快照分开 | users、sessions、surveys、fill_progress、responses；题目嵌入问卷，进度和正式答卷独立 |
| 历史语义 | 暂停修改、原链接重新发布，答卷按历史快照和版本统计 | 第一阶段发布后冻结配置，需修改时新建问卷；保存survey_revision，不伪称拥有完整快照版本管理 |
| ID与数值 | ObjectId；数字通过字符串传输，用decimal.js/Decimal128精确处理 | 字符串UUID；普通JSON/BSON数值，限制有限范围；满足当前数值题，不承诺任意小数精度 |
| 跳转 | 稳定ID、首条匹配、前后端共用TypeScript逻辑 | 稳定ID、jumps数组顺序首条匹配；浏览器调用Python后端解释，提交再重算路径 |
| 返回改答 | 描述为清理无效分支，保留仍有效回答 | 当前保守清理后续答案后重新作答；含义明确，避免旧后缀误保存 |
| 填写草稿 | 报告明确未将自动保存／断点恢复列为阶段一必做 | 下一题校验后保存fill_progress，刷新恢复；当前题未确认输入不自动保存 |
| 提交一致性 | 副本集跨文档事务，答卷与计数共同提交或回滚；内容摘要校验重试 | 单文档原子准入、唯一索引和request_id；统计只读实际responses，未采用跨集合事务，重复ID返回原回执 |
| 创建者预览 | 浏览／模拟两种模式，填写按10题分页 | 单题校验预览及正式逐题填写；未实现全卷双模式预览或10题分页 |
| 验证 | 描述36项用例、人工mongosh验收及事务故障检查 | 当前38项自动化及单列浏览器记录；不借用对方数量、截图或个人经历 |

两种模型都需说明其业务约定。课程未要求为第一阶段使用相同语言、发布快照、Decimal128或副本集事务。当前不为模仿参考重写技术栈；第二阶段在现有结构上扩展题目版本与复用，保留数据和回归用例。

## 2. 另外一份参考的边界

杨子炫报告的方案比较、集合图与测试分类表有助于解释设计。其“匿名填写无需登录”与本届原文“填写者先登录”有冲突，本项目继续采用登录后对创建者匿名。参考声称113项测试不等于我方执行结果；没有证据确认其具有独立填写进度恢复，不推断支持或不支持。

## 3. 本轮实际借鉴及代码优化

| 检查场景 | 修正 | 实现及验证位置 |
|---|---|---|
| 选择题改文本，已有跳转被隐藏 | 保留显式移除入口及提示，不静默删除规则 | frontend/app.js；browser_stage1_boundary.js |
| 新建草稿首次保存连点 | 保存操作锁和按钮禁用，完成／失败后释放 | frontend/app.js；延迟请求时双submit验证只发1次POST |
| 统计失败残留、筛选响应乱序 | 加载前清空，失败状态，请求序号／问卷／页面校验 | frontend/app.js；延迟和503故障注入浏览器验证 |
| 预测未来revision并发更新 | 客户版本等于读取快照，再以该版本执行CAS | backend/app.py；test_revision_boundaries.py的4项 |
| 回答数、选项数等分开查导致读不一致 | 单次facet聚合，各分支共享同批输入 | backend/statistics.py；真实Mongo读后插入调度回归 |
| 单题合法但整卷请求过大 | 请求上限8 MiB；保留超限拒绝 | backend/app.py；20×5000汉字进度／提交及超限413 |

这些修正来自本项目实际复核，不表示发现参考作者有相同错误。新增7项自动化与原31项共同完整执行，38项通过；浏览器结果另列，不凑入自动化数量。技术证据见tests/results/第一阶段参考优化-2026-10-22.md。
