## 对当前项目的启发

1. 题目嵌入或独立都可合理。第14组和本项目都倾向嵌入；第17组独立保存。当前课程规模下，题目随问卷读取、有限数量及单文档编辑支持嵌入；不要仅为匹配参考更改集合。
2. 阅读时 users/sessions/surveys/responses 四集合包含会话，不应与第17组“四个核心业务集合”按数量比较优劣。同日后续新增fill_progress，当前共五集合；Schema 和 API 以真实代码为准。
3. 第17组报告声明保存中途填写进度；本项目在本次阅读时只保存成功提交；同日后续开发已增补独立进度保存，详见需求与进度.md。原文“每次填写都应该被保存”对此存在解释空间，需显式记录并请学生确认是否需要恢复进度，不把参考行为自动升级为硬性要求。
4. 第14组多选跳转为恰好集合相等；本项目 any/all 是包含任一/包含全部，all 允许额外选项。原文未限定具体匹配算子，两者是不同的可配置语义，不应混称完全匹配。当前 first-match 解决多条命中优先级，不必为消除歧义放弃 any/all。
5. 第17组第二阶段的“模板版本 + 问卷快照”值得保留为候选。即使现有题目嵌入问卷，也可以将题库独立保存，导入时复制到 questions 并增加来源 ID/版本，不必先拆掉现有结构。此次不实现，待正式新要求。
6. 本项目报告可参考“需求/问题→选择→原因与取舍→测试证据”，保留必要页面及测试示例即可，不追求19页篇幅。原始设计、模型建议、真实用户反馈应分清，不能复制他人的 AI 使用经历。

## 不宜照搬及需谨慎的表述

- 第14组第5页将关系数据库方案说成需要扩展表或 EAV，且性能不佳，过于绝对。关系数据库也能使用 JSON 等方案；MongoDB 灵活结构仍需 Schema 校验、迁移和版本管理。
- 第14组第10页路径伪代码用 if ans 判断是否执行跳转，会使合法数字 0 被视为无答案。应区分未回答与 0；这是报告伪代码问题，未读源码不能断言真实程序同样有错。
- 第14组第9页统计明细限制20/50条，未说明如何继续读取。原文要求查看所有填写内容，应提供全量或可遍历分页，不能无提示截断。当前项目全量返回，课程规模可用，扩容时应分页。
- 第14组第16页“选项计数之和等于总答卷数”只适用于每份答卷都有效回答该单选题的测试前提；多选、跳题、选答不满足该恒等式。
- 第14组第18页“AI 没有错误/不需要调整”与第19页记录前端小数输入等修正，表述易造成不一致。我们的日志按真实发现及实际修正者写，不能笼统称零错误。
- 第14组匿名身份统一为 -1；若还要禁止重复，需要独立可靠机制。报告未充分说明，不能由此认定已正确支持匿名防重复。当前匿名对创建者隐藏、内部留关联，也是需明确披露的另一种取舍。
- 第17组第一阶段第7页“所有必答题”需结合跳题解释为有效路径中的必答题；仅从报告无法确认源码是否如此。我们的实现明确重算路径。
- 第17组第二阶段报告称72项测试通过，只说明所列测试范围内情况，不能证明全部兼容。跨版本统计也要处理题型、选项和单位变化，不能简单混合计数或平均；共享题库不应自动授予其他问卷答卷访问权。
