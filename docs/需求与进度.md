# 第一阶段需求核对

依据两份作业文件的初始需求开发。2026-10-15用户明确“先按照现有的做，没有的话以文件为准”，因此采用以下设计约定完成基础功能。未收到的课堂补充和第二阶段变更不作为已知要求。

| 原始需求 | 实现 | 验证 |
|---|---|---|
| 注册登录、管理自己的问卷 | MongoDB账号与会话、owner_id查询 | 认证与归属API测试 |
| 标题说明、匿名设置、列表 | 草稿工作台与设置 | 创建、编辑及浏览器流程 |
| 发布、截止、关闭、分享URL | draft→published→closed、时区截止、/survey/{id} | 状态测试与浏览器发布关闭 |

| 代码、Schema、说明、测试、报告、AI记录 | backend/frontend/database/docs/tests/reports/ai_logs | 仓库及实际结果 |

## 对未明确规则的约定

- 填写者必须登录；匿名是对问卷创建者隐藏账号，内部保留user_id控制重复，不声称不可追溯。
- 创建者允许匿名时，填写者可以选匿名或实名。
- 只向后跳或END；第一条匹配生效，未匹配进入下一题。多选any是包含任一条件项，all是包含全部。
- 提交只校验实际路径的必答题；拒绝路径外答案；前端修改前面答案后清理后续答案。
- 发布后题目与设置固定，可关闭但不重新开放。需修改时创建新问卷。
- 截止按服务器UTC时间比较。关闭前已原子准入的提交允许随后保存。
- 每次成功提交保存一份答卷。未提交的中间草稿不写库，刷新填写页重新开始；如课堂补充要求自动保存，再扩展。
- 统计按答卷份数。空选答与跳过题不计单题回答数，无数字答案时平均值为空。

以上是实现约定，非教师逐项指定。阶段一基础功能和六类测试已实现，实际结果见tests/results/latest.json和浏览器检查记录。自动化数量不包含浏览器流程，也不把一项测试中的多个断言重复计数。
